# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Напишите в Telegram [@magashihman](https://t.me/magashihman) или через [приватное сообщение об уязвимости на GitHub](https://github.com/minchiki/max-messenger-mcp/security/advisories/new). Ответим в течение 3 дней; исправление критичных проблем — в приоритете.

## Модель угроз

| Угроза | Защита |
|---|---|
| Чужой узнал адрес сервера (режим одного аккаунта) | секретный путь не короче 24 символов; при утечке смените `MAX_SECRET` |
| Кража доступа через ссылку входа (многопользовательский режим) | код авторизации возвращается только на разрешённые адреса (`MAX_REDIRECT_HOSTS`, localhost, схемы редакторов); PKCE; страница показывает, какое приложение просит доступ |
| XSS на странице входа | экранирование, CSP без внешних источников, запрет фреймов, проверка ссылки QR |
| Утечка базы или резервной копии | сессии MAX зашифрованы (Fernet, `MAX_MASTER_KEY`), токены хранятся как SHA-256 |
| SSRF через ссылки на файлы | только публичные IP, соединение на проверенный адрес (без DNS rebinding), лимит размера |
| Prompt injection из чужих сообщений | очистка невидимых символов, ограничение длины, инструкции клиенту; инструменты записи требуют подтверждения; `READ_ONLY=1` |
| Злоупотребление отправкой | белый список чатов, лимит в минуту на аккаунт |
| Перебор и спам входами | лимиты nginx на вход и регистрацию, не больше 20 одновременных входов, лимит пользователей |
| Секреты в журналах | журнал запросов выключен; тексты сообщений не логируются |

## Что не закрыто кодом

- **Взлом самого сервера.** Ключ шифрования лежит на том же сервере: шифрование защищает базу и копии, но не работающую машину. Держите систему обновлённой, вход по SSH — только по ключу.
- **Фишинг QR.** Злоумышленник может прислать человеку свой QR входа в MAX напрямую, минуя этот сервис. Сканируйте QR только на странице, которую открыл ваш ассистент.
- **Неофициальный протокол.** MAX может изменить протокол или ограничить автоматизацию аккаунтов.
